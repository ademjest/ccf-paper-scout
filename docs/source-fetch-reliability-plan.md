# 论文来源抓取与摘要补全优化方案

日期：2026-11-04。状态：核心抓取、恢复与缓存改造已实施；验证结果及条件性未启用项见 [实施记录](source-fetch-reliability-implementation.md)。

本文保留设计目标与验收要求；实际完成范围和测试数据以实施记录为准。与现有设计的关系：在多来源采集基础上提高可靠性，不重新搭建采集框架。

参考：[多来源升级方案](multi-source-upgrade-plan.md)、[多来源实施说明](multi-source-implementation.md)、[搜索反馈与评估](search-feedback-and-evaluation.md)。

## 1. 目标与边界

在相同请求次数和耗时预算下，提高有效论文信息与可信摘要的覆盖率；使单篇失败可恢复，来源异常可解释，手动搜索优先使用已有数据。

约束：

- 复用现有来源适配器、独立 worker、父进程事务提交、SQLite 状态与身份匹配机制。
- 不通过放宽主会资格、降低身份匹配要求或生成摘要来提高覆盖率。
- 不将增加并发、延长超时、追加来源作为默认解决办法。
- 不引入分布式队列、独立爬虫服务或默认浏览器自动化；先使用现有进程和持久状态。
- 本轮不调整推荐排序算法；过滤无摘要结果也不等于算法质量改善。
- 搜索库与 Daily 状态继续隔离；保留历史投递 ID、用户标注及冻结评估快照。

## 2. 当前实现与问题

### 2.1 已有能力

- `source_http.py`：可信 HTTPS 域名、请求间隔、响应大小上限、有限重试、超时、Retry-After 及部分挑战页面识别。
- `sources.py` / `source_worker.py`：来源隔离、总截止时间、取消、来源冷却、完整页消费与持久化。
- `source_adapters.py`：官方目录 HTML 解析、论文详情提取、来源记录归一化。
- `official_abstracts.py`：摘要容器解析、最低质量检查，以及已知论文补摘要时的标题和作者校验。
- 已有精确补全机制：调度器会给缺摘要候选预留部分来源预算，支持 OpenAlex/Crossref DOI 查找，以及页面定位器覆盖的官方来源。因此本方案是完善补全调度和状态，不是从零新增第二套补全链路。

### 2.2 待解决的问题

1. 官方目录发现与逐篇详情读取耦合：详情请求消耗预算，目录已发现的信息缺少独立持久化阶段。
2. `official()` 中的单篇请求或解析异常可能结束该来源当前任务；已提交结果仍在，但后续正常论文可能没有机会处理。
3. 已处理链接与摘要完成状态未充分分离；已有补全机制可以修复一部分缺失，但覆盖范围、原因状态与恢复路径仍需统一。
4. 摘要主要依赖少数 HTML 结构；`description` 回退及长度检查不能充分保证正文真实性。
5. 来源级协议错误与单篇解析错误需要区分，避免单篇字段缺失导致整个来源长时间冷却。
6. 当前诊断应进一步区分网络失败、访问限制、内容缺失、解析失败和预算耗尽。

## 3. 目标流程

```text
已核验论文集目录
    ↓ 有界采集与缓存
保存目录条目、成员证据、待获取详情状态
    ↓
本地搜索与候选筛选 → 优先级排序 → 有界详情/摘要补全
    ↑                                  ↓
    └──────── 保存可信字段与来源记录 ────────┘

官方页面失败 → 按论文身份查找可用替代来源
单篇失败     → 保存原因与下次尝试时间，继续其他论文
来源受限     → 停止该来源，保留成果并使用其他来源/缓存
```

目录条目可能只有标题和链接，尚不足以组成正式候选。应作为发现任务保存；达到现有候选数据契约后再进入候选库，不伪造作者或绕过身份检查。

## 4. 具体改造

### 4.1 错误分类与故障隔离（P0）

| 情况 | 处理范围 | 恢复策略 |
|---|---|---|
| 单篇 404、字段缺失、详情解析失败 | 单篇 | 保存原因，继续后续条目；设置较长补查间隔 |
| 单篇连接或读取超时 | 单篇，连续发生时来源级 | 有限重试后延期；连续失败达到明确阈值时停止该来源 |
| HTTP 429 | 来源/主机 | 遵守 Retry-After，停止持续访问，延后任务 |
| 401、403、挑战页面 | 来源 | 保存权限或访问限制原因，暂停，不重复绕过 |
| 连续 5xx、连接失败 | 来源 | 有限退避后暂停，保留已完成数据 |
| 目录结构不匹配 | 对应目录 | 保存解析失败诊断，不认定为空目录；其他独立目录可继续 |
| 请求预算或截止时间耗尽 | 本轮任务 | 标记部分完成，保留断点；不视作站点故障 |
| 用户取消 | 本轮任务 | 提交已接收完整结果，退出；不触发故障冷却 |
| 数据库或事务错误 | 当前运行 | 显式失败，不作为网页异常吞掉 |

仅在单条目边界捕获预期的网络及解析异常，不使用宽泛异常捕获掩盖程序错误。来源级限流或访问阻断不得被单篇隔离逻辑吞掉后继续请求。

验收：同一目录中插入一个失败页面，其后正常页面仍可保存；429 后不会继续遍历详情；已完成记录不会因任务中断丢失。

### 4.2 分离目录发现、详情读取与摘要补全（P1）

最小状态设计应先核对现有任务断点和来源记录结构，能够扩展复用时不新增平行表。若目录条目无法满足候选表契约，可增加一个职责明确的持久任务表。

建议逻辑字段（设计字段，并非当前已提供的配置/API）：

| 字段 | 用途 |
|---|---|
| 来源、目录 URL、论文 URL | 确定发现任务及去重键 |
| 目录标题、成员证据、规则版本 | 保留发现依据；主会核验仍执行原规则 |
| 详情状态 | 待处理、已获取、失败待重试 |
| 摘要状态 | 待获取、有效、原站未提供、解析失败、身份冲突 |
| 尝试次数、最近尝试时间、下次尝试时间 | 支持恢复与分原因退避 |
| 失败代码、HTTP 状态 | 支持诊断；不得记录凭据 |
| 摘要来源 URL、提取方式、获取时间 | 支持字段追溯 |

“原站未提供”只表示某次观察到的来源结果，不是永久禁止从其他来源补全。一个来源没有摘要不能覆盖其他来源的有效摘要。

执行顺序：先持久化目录发现，再按预算读取详情；优先补齐当前查询靠前、尚无有效摘要的候选，同时保留一部分预算发现新论文，避免补全任务长期占满采集额度。沿用现有全局和每来源预算，避免重复记账或额外无界请求。

手动搜索先返回本地结果，再按现有交互机制更新补全结果。历史冻结快照不回写；新数据只进入新搜索快照，保持评估可复现。

### 4.3 摘要提取与质量检查（P1/P2）

采用共享字段规范化与少量平台规则，避免建立复杂的通用解析插件体系。每增加一种提取方式，都先确认目标平台实际存在对应结构。

候选提取方式：

1. 官方 API/数据文件中明确的摘要字段（平台实际提供且适合当前任务时）。
2. 页面明确标识的摘要正文容器。
3. 明确的摘要元数据或可归属于当前论文的 JSON-LD `abstract` 字段。
4. 通用 `description` 仅作为待校验候选，不自动升级为可信摘要。

检查内容包括：正文非空、基本长度、无导航或挑战文本、不是引用格式占位内容；补全已有论文时必须验证身份。长度达标只是最低过滤条件。JSON-LD 页面可能包含多个对象，不能取第一个对象的文本作为论文摘要。

多个提取方式冲突时保留诊断和来源，不覆盖已有可信摘要。主会分区不明确时保留待核验状态，不因摘要成功而授予主会资格。

### 4.4 跨来源精确补全（P1）

| 可用标识 | 首选路径 | 约束 |
|---|---|---|
| 已知官方详情 URL | 对应官方页面 | 补全时验证标题、作者，记录来源 |
| DOI | 已配置可用的 OpenAlex/Crossref 精确接口 | 响应 DOI 必须匹配；接口未提供摘要时保留缺失 |
| 已确认的其他来源 ID | 对应已支持接口 | 不从页面字符串猜测身份关系 |
| 只有标题、作者、年份 | 保守查找或待核验 | 不凭同名论文自动合并；沿用现有身份策略 |

主会资格证据和摘要来源分别保存。预印本与正式版本存在关联时仍保留版本差异，不因标题相近直接互换摘要。复用现有 DOI 精确查找，只有覆盖缺口经实测确认后才扩展新的查找接口。

### 4.5 缓存与后台刷新（P1/P2）

- 稳定详情页优先复用，不在每次搜索时重复抓取。
- 目录按明确刷新周期更新；初期由现有 CLI/运行入口执行有界刷新，之后才考虑复用既有定时工作流，无需先建设常驻服务。
- 服务端支持时保存 `ETag`、`Last-Modified` 并发送条件请求。
- 收到 304 必须能读取对应缓存正文或已解析数据；缓存不存在时不能将 304 当作空页面成功，所需补请求仍计入预算。
- 缓存键应区分 URL、影响响应的参数以及必要的访问上下文，日志与键中不暴露 API 密钥。
- 解析规则升级后允许对缓存内容重新解析；缓存保存范围和清理策略应有界，避免无限保存所有网页。
- 同一域名未来被多个适配器访问时，共享访问节奏，不能通过增加适配器数量绕过限制。

### 4.6 用户可见的诊断（P0/P1）

建议显示：来源状态、失败原因、下次尝试时间、当前使用实时还是缓存数据，以及本轮新增和补全数量。示例：

```text
PMLR：部分完成；新增 8 篇，补全摘要 5 篇，2 篇详情页超时待重试。
NeurIPS：本轮未访问；处于冷却期，原因是上次连接超时。
当前结果：20 篇，其中 18 篇有有效摘要；部分记录来自历史缓存。
```

上述数字仅为展示样式，不代表实际运行结果。“搜索完成”表示任务结束，应另外说明来源覆盖与摘要覆盖。

## 5. 来源访问策略及反爬边界

下表是渠道选择原则，不是各平台当前访问政策的实时核验。实施前应核对官方接口说明、robots.txt（如适用）、使用条款与额度；不能把一次超时推断为反爬。

| 来源 | 优先方式 | 优化重点 |
|---|---|---|
| PMLR、NeurIPS、ACL Anthology | 已审查目录和详情页；适用时采用官方结构化资源 | 目录缓存、单篇隔离、摘要解析与分区证据 |
| CVF、AAAI | 已核验会议目录/卷期与详情页 | 明确页面结构和摘要字段，避免泛化到未核验轨道 |
| OpenAlex | 官方 API、DOI 精确查找 | 额度管理、摘要倒排结构还原、缺失状态 |
| Crossref | 官方 REST API、DOI 精确查找 | 身份信息及实际存在的摘要；不假设所有记录有摘要 |
| DBLP | 当前已接入的官方查询接口 | 书目发现和身份关联；不承担完整摘要提供职责 |
| arXiv | 官方 API或适合需求的官方数据渠道 | 访问间隔、版本信息、预印本身份 |
| Semantic Scholar | 已授权且可用的官方 API | 配额、密钥、字段缺失及限流处理 |
| OpenReview | 官方 API | 权限、投稿/录用状态区分及配置范围 |
| 商业出版平台 | 授权接口、开放元数据及开放获取版本 | 访问权限、全文使用范围；不作为本轮新增抓取目标 |

不绕过验证码、登录、付费墙或明确的访问阻断。遇到限制时记录并切换可用来源。题名和摘要的访问权限不等同于全文批量下载权限。

## 6. 实施顺序与代码落点

| 阶段 | 最小交付 | 主要代码落点 | 通过条件 |
|---|---|---|---|
| P0：可解释、可隔离 | 单篇异常隔离、错误分类、原因显示 | `source_adapters.py`、`sources.py`、必要的 worker 结果契约及网页状态展示 | 故障样本不影响后续正常论文；限流/取消仍正确停止 |
| P1：可恢复、可补全 | 目录任务持久化、摘要状态、复用精确补全调度 | `state_store.py`、`source_adapters.py`、`sources.py` | 中断可恢复；没有重复候选、错误合并或无界请求 |
| P1：搜索可复用 | 有界刷新、本地优先、补全结果更新 | `search.py` 及现有 CLI/web 入口 | 重复搜索减少外部访问；旧快照不变 |
| P2：提取与缓存效率 | 平台字段补充、条件请求、缓存再解析 | `official_abstracts.py`、`source_http.py`、适配器及必要状态 | 提取准确性不降低，相同预算下覆盖率或耗时改善 |

正式实施前核对当时最新代码，避免与并行开发重复实现。每阶段单独评审与验证，不将全部设计一次性堆进主流程。

## 7. 验证与验收

### 7.1 固定数据离线验证

使用同一批目录与详情响应，覆盖正常摘要、缺字段、404、超时、429、挑战页面、目录结构变化、多个 JSON-LD 对象和缓存 304。样本按页面结构和失败类型选择，不按特定论文名称编写条件。

必须验证的行为：

- 单篇失败后，后续正常论文仍可处理。
- 429 和来源级阻断不被吞掉；预算、截止时间和取消仍生效。
- 已提交页及断点一致，中断恢复不重复创建候选。
- 有效摘要不被空文本、站点描述或较低可信文本覆盖。
- DOI/作者身份不符时不补错摘要，不授予错误主会资格。
- Daily 已投递记录、人工标注和历史冻结快照不被迁移改变。

### 7.2 小预算线上验证

在离线检查通过后，选 PMLR、ACL、NeurIPS 及一个可用聚合来源做小规模验证。建议首轮各来源不超过 10 次 HTTP 请求、总计不超过 40 次；重试与跳转也计数，不通过反复运行规避预算。该额度是后续测试建议，本次文档编写不执行线上请求。

对网络失败记录真实原因；来源不可达时不承诺摘要覆盖率必然提升。线上前后对比受网络和数据更新影响，主要用于验证可运行性；解析和恢复能力以固定响应回放为主要证据。

### 7.3 核心指标

| 指标 | 定义与用途 |
|---|---|
| 有效摘要覆盖率 | 固定候选池中通过质量检查的摘要数 / 候选数；不得先过滤无摘要记录再计算 |
| 展示摘要覆盖率 | 展示结果中有有效摘要的比例；与候选池覆盖率分开报告 |
| 单位请求产出 | 固定任务中新增完整记录数或新增有效摘要数 / 实际 HTTP 请求数；分别统计 |
| 解析准确性 | 人工核验样本中，提取文本确为对应论文摘要的比例 |
| 恢复能力 | 故障后待处理任务能继续完成，且无重复候选和身份错误 |
| 搜索耗时 | 首次本地结果时间与后台补全完成时间分别记录 |
| 来源异常分布 | 网络、限流、权限、解析、内容缺失与预算耗尽分别统计 |

不预先承诺“成功率达到 95%”等缺乏基线的目标。先记录现有基线，再在相同候选、响应和预算条件下比较；未提升时保留证据并调整方案。

## 8. 发布、回退与后续范围

- 数据结构变更采用可迁移方式，先在数据库副本验证，保留原有论文 ID 与投递去重信息。
- 搜索与 Daily 分别验证，先进行本地/预览运行，不用真实投递验证解析器。
- 优先利用现有 shadow/隔离运行方式；不为每个细节新增永久开关。
- 回退时恢复兼容代码或迁移前数据库副本，不重置私有仓库历史或删除 seen 记录。恢复副本前须确认之后没有新增投递/标注，避免覆盖新状态。
- 本轮不实施 PDF 抽取、默认浏览器渲染、大规模全文下载或推荐模型重训。只有数据证明现有渠道仍无法满足需求时，再单独评估这些扩展。

推荐首先落地 P0 的错误分类与单篇隔离，再改进已有补全调度和任务状态；在能够解释失败、可靠恢复后，开展缓存与解析覆盖优化。
