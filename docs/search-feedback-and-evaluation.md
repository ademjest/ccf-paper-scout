# 搜索历史、协作标注与离线评测

本轮交付：持久化搜索历史、按查询保存相关性反馈、人工与 AI 来源分离、固定快照导出及离线评测。搜索排序仍沿用词项算法，本轮不以功能增加宣称相关性已经提升。

## 1. Windows 使用

手动搜索默认采用“正式期刊／会议论文”范围，排除预印本、学位论文、书籍及发表状态不明确的记录。默认来源为 OpenAlex 和 PMLR、NeurIPS、ACL、CVF、AAAI 官方论文集；arXiv、Crossref 保留为显式选择的补充来源。若只阅读已核验的 CCF-A 主会论文，选择“仅已核验主会”。正式发表不等于主流会议或论文质量保证。

Crossref 的 DOI 注册记录包含多种文献，不能统一视为正式论文。适配器保留文献类型，仅将期刊／会议论文类型标为正式发表；OpenAlex 还要求主位置明确标记已发表。旧缓存中只有 `published`、缺少文献类型证据的非主会记录暂按状态未核实处理，重新获取元数据后才能进入默认范围。已有正式主会核验证据优先，不因同时存在预印本版本而排除正式版本。

Crossref 仍可用于精确 DOI 元数据补全；这不等于需要将它用于广域候选检索。当前仍按已启用来源安排补全，本次没有新增后台常驻补全任务。默认取消勾选来源只控制新请求；缓存中有合格发表证据的论文仍可被搜索到，不按数据提供方整库删除。旧搜索快照与标签保留当时条件，新的排除偏好只作用于新搜索，不能把同一批历史相关性标签直接改成质量判断。

更新安装后，停止原来的本地服务，再启动并刷新网页：

```powershell
Set-Location E:\Agent\ccf-paper-scout
$env:PYTHONUTF8 = '1'
.\.venv\Scripts\python.exe -m pip install --no-cache-dir .
.\.venv\Scripts\ccf-paper-scout.exe serve --config config.example.json
```

打开 `http://127.0.0.1:8765`。“最近搜索”中选择记录并点击“查看结果”，重启服务后仍可恢复。历史卡片保留当时的题名、摘要、次序、分数、来源状态、查询条件和耗时；后续更新候选库不会改写已完成的快照。

日常界面优先显示搜索、年份、发表范围与论文卡片；来源开关收在“来源与搜索选项”，抓取原因与耗时收在“查看来源与检索详情”。评测分组和导出收在“反馈数据与评估（可选）”。这些是界面调整，未更改查询、排序或数据含义。

服务应从可以访问论文网站的普通 Windows PowerShell 启动；由自动化工具启动时也必须使用获准联网的运行环境。若所有来源在几秒内同时失败且收到字节为 0，应先检查服务进程的网络权限及代理，而不是扩大关键词或延长超时。`connection_failed` 表示连接失败，`transport_timeout` 才表示连接或读取超时；修复环境后，旧历史记录仍保留原错误，新的搜索也可能需要等待来源冷却结束。

新版开始记录新搜索，不能恢复旧版未保存的查询历史。现有候选、收藏、已读和旧论文级相关性数据保留；旧相关性没有查询上下文，因此不会自动转成查询级标注。

网页默认勾选“仅显示有摘要”，在排序前排除缺少有效摘要的记录；取消勾选可恢复包含题名记录的检索。该筛选会写入快照条件，页面同时显示被排除的数量及结果摘要覆盖。CLI 用 `--require-abstract` 显式启用。历史快照保持原样，打开旧记录会恢复当时的筛选条件；需要新条件时重新搜索。

此项是标注资料完整性筛选，不是摘要补全或排序算法提升。原词项基线将题名和摘要共同归一化，可能偏向标题匹配的短记录；后续仍需用固定候选对照评估排序。首批标注准备遗漏摘要覆盖检查的问题已经修正，并从现有缓存重建带摘要的新快照，原快照和反馈不删除。

网页显示本地候选、年份/身份排除、发表范围排除、零词项匹配与最终展示数量。来源冷却时显示错误码和可重试时间；“部分来源未完成”与“本地缓存搜索完成”分别展示。计数来自本轮最多读取的 100,000 条缓存候选，不等于互联网全部匹配数量。

## 2. 可以只标一部分，其余协作完成

标注单位是**某次查询下的一篇论文**，而非这篇论文是否普遍符合个人兴趣。同一论文对不同问题可以得到不同分数。每张卡片通过“对这次搜索有帮助吗？”选择反馈，用“保存反馈”提交；理由与 AI 参考意见按需展开。界面使用阅读语言，导出分值保持不变：

| 分数 | 判断标准 |
|---|---|
| 2（很有帮助 · 直接相关） | 直接回答查询关注的问题，方法或研究对象具有阅读价值 |
| 1（有些帮助 · 可以借鉴） | 有部分关联或可借鉴内容，但不是查询的核心需求 |
| 0（没有帮助 · 不相关） | 研究问题不匹配，仅有词语重叠等表面关系 |
| 待判断（还没判断） | 题名/摘要不足以判断，或尚未阅读；不是 0 分 |

例如检索“LLM 辅助 RL 奖励设计”时，应区分“用 LLM 帮助设计 RL 奖励”与“用 RL 训练 LLM”。理由可以只写一句，指明论文研究对象或方法与查询的关系。缺摘要时可以打开论文主页，不必凭标题强行判断。

推荐协作顺序：

1. 选 5–6 个开发查询，各人工标约 2 篇，共 10–12 个组合。尽可能覆盖不同相关程度，但不要为了平衡数量改动真实判断。
2. 导出“AI 待标注包”，或告诉工作区中的助手已经完成。助手读取开发包中的人工示例和未标注论文，再按查询补充建议。
3. AI 每条建议保存分数、理由、标注者/模型标识和快照指纹；证据不足保留待判断。AI 不确定或与你判断冲突的条目优先人工复核。
4. 网页同时显示 AI 建议和人工判断。AI 不会覆盖已有人工标签；人工可通过“保存反馈”确认或修正建议。

当前 AI 辅助流程为“导出 → 助手补全 → 导入”，没有后台自动调用 LLM。未标注且缺摘要的条目不会进入 AI 待标注任务，导出会报告暂缓数量。标注者自行填写的模型名称是来源记录，不是对模型输出准确性的担保。

无需全部标完才能使用搜索或进行开发。首轮可只标少量开发样本，然后逐步补充；不要将 AI 标注直接当作独立测试真值。

## 3. 开发与独立测试

如需分组，在搜索前展开“反馈数据与评估（可选）”，选择本次反馈用途：

- **日常阅读 · 可参考 AI 建议**：对应原开发样本 `dev`，可协作评阅，用于理解偏好、分析错误和后续调参。
- **独立评估 · 只记录我的判断**：对应原独立测试 `test`，只接受人工标注，不进入 AI 任务包，也不允许导入 AI 标签。用于最终报告时应在调参前预留，不根据测试结果反复改算法。

同一标准化查询（忽略大小写和重复空白）不能跨开发/测试组。分组按查询，不随机拆“同一查询下的论文”来制造独立测试。近义或高度相似的查询仍需人工审查分组；软件不能保证它们在语义上独立。

同一查询多次检索会形成不同快照，标签不自动跨快照迁移，以免把旧摘要下的判断套到更新的证据上。收藏和已读仍按论文保存。

首批个人工作区标注任务由缓存生成：6 个开发查询 × 5 篇、2 个测试查询 × 5 篇。可先标约 12 个开发组合，其余开发组合由助手参考补充；10 个测试组合可以另择时间完成。这个小样本用于验证流程和发现明显问题，不足以证明对广泛查询的效果提升。

## 4. 导出与评测

网页“导出搜索与反馈”包含开发和测试数据，属于个人研究记录；“导出待协助评阅清单”只包含开发示例及未标注任务。已有人工“待判断”的条目保留供人工复查，不会被自动替换成 AI 答案。

默认每个标准化查询选择最近一次完成或取消的快照，因此重新搜同一查询不会增加该查询在评测中的权重。需要使用较早的已标注快照时，在 CLI 指定 `--search-ids`。不要在补充标注后无意中用新的未标注快照替换评测集。

```powershell
# 查看历史，取得 search id
.\.venv\Scripts\ccf-paper-scout.exe search-history --config config.example.json

# 冻结并导出结果与当前标注
.\.venv\Scripts\ccf-paper-scout.exe search-export --config config.example.json --output local-notes/search-benchmark.json

# 仅导出开发示例和 AI 待标注任务
.\.venv\Scripts\ccf-paper-scout.exe search-export --config config.example.json --ai-tasks --output local-notes/ai-label-tasks.json

# 助手填写任务包 labels 中的 grade / reason / actor 后导入，来源强制记录为 AI
.\.venv\Scripts\ccf-paper-scout.exe search-import-ai --config config.example.json --input local-notes/ai-labels-completed.json

# 基于同一快照评估原始次序；无网络、无需 Zotero / SMTP / LLM
.\.venv\Scripts\ccf-paper-scout.exe search-evaluate --input local-notes/search-benchmark.json --output local-notes/search-metrics.json --k 5

# 对冻结的题名和摘要重新执行词项排序
.\.venv\Scripts\ccf-paper-scout.exe search-evaluate --input local-notes/search-benchmark.json --output local-notes/search-lexical-metrics.json --ranking lexical --k 5
```

导入 AI 文件时，快照指纹、论文身份、分数与来源必须有效；整批导入使用一个事务，错误行不会留下半批结果。空模板不会被当作已完成标注。开发组和测试组中都只用人工标签计算本轮指标，AI 建议数量另行统计。

### 指标含义

| 指标 | 计算与缺失处理 |
|---|---|
| Precision@k | 前 k 位中人工标为 1 或 2 的数量 / k；只在实际返回的前 k 位均有人工判断时计算 |
| Strong Precision@k | 前 k 位中人工标为 2 的数量 / k，条件同上 |
| nDCG@k | 收益为 `2^grade - 1`；仅在整个冻结结果池都有人工作答，且存在正收益时计算 |
| 标注覆盖率信息 | 每查询显示池大小、人工已标数量、前 k 位已标数量和 AI 建议数量 |
| 耗时 | 保存本地缓存首轮计算与总查询耗时；不是“用户找到有用论文”的时间 |

未标注不当作 0；条件不足时指标为 JSON `null`。返回不足 k 篇时，Precision 的分母仍为 k，缺少的位置贡献 0；这与“返回了论文但尚未判断”不同。开发/测试分别汇总，并报告每个指标实际纳入的查询数。对部分完成的查询报告均值时必须一起看覆盖率，不能把它当作完整测试集成绩。

此评测衡量捕获结果池中的排序/相关程度，不计算全库 Recall。首批仅固定每查询前 5 篇，不能据此判断未进入前 5 的论文是否被遗漏；后续比较多个检索器时需冻结它们结果的合并池并补标。

### 后续比较其他排序

`--rankings` 可读取以下结构。每个查询必须使用相同 `snapshot_hash`，并完整排列原冻结池中的每个 ID 一次，不得加入新论文或省略不利样本：

```json
{
  "schema": "scout-search-rankings-v1",
  "queries": {
    "实际 search_id": {
      "snapshot_hash": "原快照指纹",
      "ranking": ["论文 ID 按新次序排列"]
    }
  }
}
```

该入口可比较同一冻结池的不同排序。网页现已接入本地向量与混合排序，使用方式与验证范围见 [网页语义搜索](search-semantic-ranking.md)。

## 5. 存储与接口

搜索库仍与 Daily 库分离。本轮只新增 `search_sessions` 和 `query_feedback` 表及查询索引，不改投递表或旧反馈。最终快照不再允许更新；标注按 `search_id + paper_id + origin` 分别保存最新人工/AI 判断，不宣称已实现所有标注修订版本的审计日志。

| 接口 | 行为 |
|---|---|
| `GET /searches` | 最近 50 次搜索的摘要 |
| `GET /searches/{id}` | 持久化快照，加上最新查询级判断及收藏/已读 |
| `POST /searches` | 新增可选 `split: dev/test`、`cached_only: bool` |
| `POST /searches/{id}/feedback` | `paper_id`、`grade: 0/1/2/null`、可选 `reason`、`snapshot_hash`；固定记为人工 |
| `POST /papers/{id}/feedback` | 只接受 `read` 与 `saved`；相关性必须走查询级接口 |
| `GET /benchmark` | 导出完整评测快照 |
| `GET /annotation-tasks` | 导出开发组 AI 任务包，不含测试查询和标签 |

原本机 Host/Origin/令牌校验继续生效。正在检索的结果还会更新，因此结束或取消后才可标注固定结果；正常失败保留已取得的快照。强制杀进程时，最后完成的历史仍存在，未正常结束的任务不自动续跑，需要重新搜索。

## 6. 评测前检查

先取得少量人工开发标签，再协作补齐开发集；AI 标签必须保留来源，不充当独立人工判断。同一导出快照可重复离线评测，用于比较排序方法。

独立测试样本应由人工确认；缺失标签保持未知，不用合成标签或 AI 标签补出正式指标。标注与评测不会自动训练模型、改变 Daily 排序或触发邮件。
