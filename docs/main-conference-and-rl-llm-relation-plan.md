# CCF-A 主会论文准入与 LLM／RL 关系识别改进方案

- 日期：2026-10-20
- 状态：待审查的设计方案，本文不代表功能已实现
- 目标：只推荐已核实的 CCF-A 主会研究论文，并区分 LLM 辅助 RL 与 RL 训练 LLM
- 实施原则：复用现有增量发现、SQLite 缓存和 GitHub Actions，不训练新模型，不引入 GPU 或额外向量数据库

## 1. 背景与已观察到的问题

当前 preview 已跑通 Zotero 读取、DBLP 发现、摘要补全、规则筛选、翻译和报告生成，但样本暴露出以下问题：

1. 会议 stream、DBLP record-key 前缀及 `Inproceedings` 类型只能说明记录归属，不能保证属于主会研究论文。
2. 推荐中出现了摘要明确说明为教程的记录，以及 DOI 指向 Findings-ACL 的论文。
3. 当前 `LLM-assisted reinforcement learning` 判断主要依赖 RL 与 LLM 词项共现，无法区分两者的作用方向。
4. 选文后的 LLM 翻译与推荐理由不是独立相关性审核，可能重复甚至强化错误分类。
5. 广义 `reinforcement learning` 主方向仍可能放行 LLM 后训练论文；仅修正第三个方向的标签不能解决准入问题。
6. 摘要补全有运行预算，尚无摘要的候选默认暂缓，因此单轮结果不代表整个候选池的充分比较结果。

已检查的诊断快照包含 17,905 篇候选、189 篇有摘要记录、151 篇通过当前规则的候选，最终输出 10 篇。这是一次样本的状态，不是覆盖率或个人推荐准确率的长期评估。

## 2. 推荐范围与边界

### 2.1 主会论文定义

建议采用以下默认定义，作为待审查的产品边界：

> CCF-A 会议正式主会 proceedings 中的研究论文，包含符合条件的长文、短文；口头或海报展示形式不影响资格。

明确排除：

- Workshop、Findings。
- Tutorial、Demo。
- 博士论坛、学生研究竞赛。
- 前言、会议介绍、勘误等非研究内容。

行业、应用、资源等轨道需要核对官方是否将其归入主会研究论文，不能仅凭轨道名称判断。未核实的轨道暂缓推荐，不自动继承会议的 CCF-A 标签。

CCF 等级归属、主会轨道归属、个人研究相关性是三个独立判断，不应互相替代。Embedding 不负责确认出版资格。

### 2.2 研究兴趣边界

建议默认保留：

- 通用强化学习方法。
- 传统多智能体强化学习。
- LLM 辅助 RL 算法设计、奖励设计、探索、规划和学习过程改进。
- 有实质多智能体学习或协调贡献的 LLM 多智能体强化学习。

建议仅针对 LLM 后训练、对齐、代码模型微调的 RL→LLM 工作默认不进入主推荐。这是待用户确认的偏好策略，不意味着此类论文本身质量较低或不属于强化学习研究。

不使用 `alignment`、`fine-tuning` 等词的简单黑名单，因为真正相关的论文也可能提及这些概念。

## 3. 主会资格硬过滤

### 3.1 从会议白名单升级为论文集白名单

按“会议＋年份”维护可审查的主会 proceedings 清单：

| 信息 | 用途 |
| --- | --- |
| 会议、会议年份 | 确定适用范围 |
| 允许的 proceedings 标识 | 精确匹配主会研究论文集 |
| 轨道及论文类型 | 区分主会、Findings、教程等 |
| 官方证据地址、核验时间 | 支持人工审查与后续刷新 |

论文集标识必须取自真实来源，不凭标题或 DOI 后缀自行构造。会议年份需要结合官方目录核验，不简单假定 DOI 年份等于会议年份。

来源优先级：

1. 官方会议／论文集目录，例如 ACL Anthology 的具体卷。
2. DBLP 记录关联的具体 proceedings。
3. 出版商目录或其他元数据作为补充核验。

先为当前扫描的两个年份和八个会议建立清单。不同会议的目录结构不统一，首轮需要适量人工核验；后续复用来源适配逻辑，新年份无法确认时只审查论文集，不要求逐篇人工审查。

### 3.2 候选资格与证据

建议为候选保存：

```text
proceedings_id
track
main_conference_status: verified / excluded / unresolved
verification_source
exclusion_reason
```

准入规则：

| 状态 | 推荐行为 |
| --- | --- |
| `verified` | 可以进入后续兴趣判断 |
| `excluded` | 不进入推荐 |
| `unresolved` | 暂缓，等待证据或人工核验 |

核验失败不能回退为“DBLP 前缀匹配即放行”。来源尚无记录与已有论文但轨道未确认需要分别报告，避免都表现为“尚未收录”。

### 3.3 历史候选迁移

- 对现有候选库重新执行资格核验，旧记录不能绕过新规则。
- 保留旧投递历史，不重置去重状态。
- 保存被排除或暂缓的原因，便于审查，而不是直接删除候选。
- 在摘要请求、embedding 和翻译前完成准入判断，避免为不合格记录消耗预算。

## 4. LLM／RL 关系分类

### 4.1 独立关系标签

| 标签 | 含义 | 示例 |
| --- | --- | --- |
| `llm_for_rl` | LLM 帮助设计或改进 RL 学习过程 | 奖励设计、探索、规划、策略初始化、RL 代码生成 |
| `rl_for_llm` | RL 用于训练或优化语言模型 | RLHF、LLM 对齐、推理或代码模型后训练 |
| `llm_multiagent_rl` | RL 用于训练、协调多个 LLM 智能体 | 多智能体搜索系统的联合策略优化 |

标签允许共存。混合论文不能被强制塞进单一类别。

“是否有实质 MARL 贡献”独立判断，不能看到 RL→LLM 就将所有 LLM 多智能体工作一起剔除，也不能仅凭出现多个 agent 就断言属于 MARL。

### 4.2 复用预训练 embedding，无需训练

继续使用项目已有的 `BAAI/bge-small-en-v1.5` 及固定模型 revision，复用分块和 SQLite 向量缓存。

为每种关系建立多条英文描述，形成关系原型，而不是只比较宽泛的研究方向名称。

LLM→RL 原型示例：

> A language model generates reward functions to improve reinforcement learning agents.

> A language model assists exploration, planning, or reinforcement learning algorithm design.

RL→LLM 原型示例：

> Reinforcement learning updates language model parameters for alignment, reasoning, or code generation.

> The language model is the policy being optimized using preference or task rewards.

LLM 多智能体 RL 原型应突出联合学习、协作、跨智能体信用分配或系统级奖励，避免仅描述多个 LLM agent 的存在。

对标题和摘要编码后，分别计算与各组原型的相似度，并记录：

```text
LLM→RL 得分
RL→LLM 得分
LLM 多智能体 RL 得分
方向分差 = LLM→RL 得分 − RL→LLM 得分
```

组内聚合方式及判断阈值需通过标注样本选择并固定版本。相似度不是概率；不能直接宣称某个分数对应某个准确率。

分差明显偏正或偏负可作为相应关系的证据。两边都高、分差接近或摘要证据不足时，标记为混合／不确定，不凭微小分差强制分类。

### 4.3 少量边界候选复核

Embedding 擅长识别相近主题，但对“谁帮助谁、谁被优化”不一定可靠，因此建议：

- 明确案例：依据校准后的规则分类。
- 边界案例：进入有预算上限的 LLM 复核。
- 缺摘要或证据不足：暂缓。

复核模型回答以下问题：

1. 谁是被优化的策略或模型？
2. LLM 在方法中承担什么角色？
3. RL 在方法中承担什么角色？
4. 是否存在实质多智能体学习或协调贡献？
5. 摘要中支持上述判断的原句是什么？

要求引用摘要中的准确原句。缺乏证据时返回“不确定”，不得根据标题自行补全方法。

每日仅复核有限数量的边界候选，避免对整个候选池逐篇调用 LLM。关系复核与最终翻译分开，翻译阶段不能覆盖准入结论。

## 5. 推荐策略及解释

| 类别 | 建议策略 |
| --- | --- |
| 通用 RL、传统 MARL | 主方向 |
| LLM→RL | 主方向 |
| 有实质 MARL 贡献的 LLM 多智能体 RL | 保留，独立标注 |
| 仅 LLM 后训练／对齐的 RL→LLM | 默认不进入主推荐 |
| 混合关系、不确定 | 复核后决定 |

必须将关系判断用于准入或排序，不能只改变展示标签。尤其不能让宽泛的 `reinforcement learning` 匹配绕过对“仅 RL→LLM”的明确偏好策略。

推荐理由应使用已判定的关系、匹配方向及摘要证据，允许明确表达：

> 本文涉及广义强化学习，但不属于 LLM 辅助 RL。

禁止要求模型为所有入选论文强行生成“与全部方向高度相关”的理由。

## 6. GitHub Actions 与成本控制

建议工作流：

```text
增量发现候选
  → 主会资格核验
  → 历史与 Zotero 排重
  → 有预算的摘要补全
  → embedding 关系分类与兴趣评分
  → 少量边界候选复核
  → 合格论文排序
  → 翻译、报告、投递
```

运行约束：

- 不训练模型，不要求 GPU，不引入额外向量数据库。
- 原型向量缓存；原型、模型或分块策略变化时更新对应缓存与校准版本。
- 论文向量按内容增量更新，避免每日重新编码整个历史库。
- 不合格主会记录不消耗摘要、embedding、复核和翻译预算。
- 初始化分多轮完成，保留现有请求与编码预算。
- 不承诺 GitHub Actions 一次完成所有历史记录，也不以单次模型 smoke 测试代替完整运行耗时评估。

现有 preview 隔离生产状态的保护继续保留。反复 preview 可能重复处理尚未持久化的摘要和模型缓存，需要在评估耗时及 API 成本时明确记录。

## 7. 样本与评估

当前推荐可作为初始案例：

| 论文 | 用途 |
| --- | --- |
| Large Language Model as an Excellent RL Researcher | LLM→RL 案例 |
| Multi-Turn RL for LLMs | RL→LLM 及教程排除案例 |
| Bayesian Inverse RL for LLM Alignment | RL→LLM 案例 |
| ReflexiCoder | RL→LLM 及 Findings 排除案例 |
| LLM-Driven Multi-Agent Search Systems | LLM 多智能体 RL 边界案例 |
| Novelty-Guided Data Reuse、Decentralized MARL Explanations、Gradient-Protected Value Decomposition | 传统 MARL 案例 |

除已由报告明确识别的教程和 Findings 外，其他记录的主会资格仍需独立核验，不能以主题相关性代替出版资格。

初步标注建议：

- 约 60–100 篇，覆盖三种关系、传统 RL／MARL、主题相近但不相关的反例。
- 分别标注出版资格、关系标签、个人是否希望收到。
- 保留独立测试样本，不参与原型选择和阈值调整。
- 当前 10 篇不同时充当校准集和最终测试集。
- 少量样本仅提供初步评估，不据此承诺长期准确率。

需报告的指标：

- 主会资格误放行与未知状态数量。
- LLM→RL 和 RL→LLM 的混淆情况。
- 混合论文、真正 MARL 论文被误剔除的情况。
- 人工评估的推荐相关性和每日合格数量。
- 摘要覆盖、暂缓数量及原因。
- CPU 耗时、模型缓存命中与 API 成本。

## 8. 分阶段实施与验收

### 第一阶段：主会硬过滤

工作：

- 建立当前会议年份的论文集清单及证据。
- 保存主会资格状态，重新检查旧候选。
- 推荐前强制执行资格判断。

验收：

- 已知 Findings、教程、博士论坛等排除样本不进入推荐。
- 未知论文集不放行，并明确报告暂缓原因。
- 已核实的主会长文、短文，以及海报展示的主会研究论文不因展示形式被误排。
- 去重及投递历史保持不变。

### 第二阶段：关系分类与推荐策略

工作：

- 建立关系原型并复用 embedding 缓存。
- 增加有预算的边界复核。
- 将关系标签用于准入与排序，修正报告解释。

验收：

- 使用独立留出样本检查关系混淆和误剔除。
- 仅 RL→LLM 工作不能通过宽泛 RL 匹配绕过偏好策略。
- 混合论文不被强制归入单一方向。
- 无摘要或无证据时不生成确定关系结论。

### 第三阶段：影子评估与正式切换

工作：

- 在不影响正式投递的情况下对比原策略与新策略。
- 审查样本、阈值、数量、耗时和成本后再切换生产。

验收：

- 具备可审查的人工评估结果，不仅是程序测试通过。
- 明确展示新策略排除了什么、是否误排以及为何保留。
- 模型、原型、策略版本变化时重新验证校准。
- 保持生产去重、SMTP 恢复、私有报告及 preview 状态隔离保护。

## 9. 结论

推荐采用“主会资格硬过滤＋关系原型 embedding＋少量边界复核”。

优先解决论文集与轨道准入，再优化 LLM／RL 关系识别。仅增加 embedding，而保留当前宽泛准入规则，无法解决已观察到的教程、Findings 混入和 LLM 作用方向混淆问题。
