# 网页语义搜索

## 使用

网页默认选择“语义＋关键词（推荐）”，也可以切换“语义匹配”或“关键词匹配”。输入英文研究问题，保留“只看有摘要的论文”，点击“查找论文”。先出现关键词结果，联网补充结束后再进行一次本地语义排序；最终排序方式显示在结果标题旁。

历史搜索保持原来的结果和排序，查看历史不会重新计算。需要比较新算法时请发起新的搜索。“停止搜索”会停止后续工作；已经开始的一批向量计算完成后响应取消，保留关键词结果。首次加载模型也需要等待当前加载结束。

CLI 为兼容已有脚本默认仍是关键词模式，可显式指定：

```powershell
.\.venv\Scripts\ccf-paper-scout.exe search --config config.example.json --query "planning with learned environment dynamics" --ranking hybrid --require-abstract --cached-only
```

## 检索与排序

1. 从独立搜索库读取候选，先应用年份、身份核验、发表范围、有效摘要筛选。默认继续排除预印本和学位论文。
2. 关键词通道复用现有 `rank_candidates`，其输入原本就包含标题和摘要。
3. 向量通道复用 Daily 的 `semantic.Encoder` 和 `semantic.rank`，但查询向量只来自本次问题，不加入 Zotero、长期兴趣、投递记录或人工标签。**不以关键词是否命中作为向量候选的门槛。**
4. 模型为固定版本 `BAAI/bge-small-en-v1.5`，CPU 推理，384 维。标题与摘要一起编码；长摘要按模型长度分段，每段带标题，默认最多 3 段，再取平均并归一化。极长摘要超出段数的部分不会参与匹配。缺少摘要时仅能使用标题，页面默认筛掉这类记录。
5. 纯语义模式按余弦相似度排序。混合模式分别取关键词、向量通道前 100 篇，使用等权 RRF：每个通道贡献 `1 / (60 + 排名)`，按总分排序；不直接相加不同量纲的词项分数与余弦值。仅有向量匹配的论文也能进入合并池。
6. 向量通道只排除非正相似度。这不是经过人工校准的相关性阈值；相似度也不是论文质量或相关概率。无相关论文时仍可能返回看似接近的结果，需要阅读和标注判断。

向量搜索范围是**已经获取的本地候选库**，并非全网向量检索；联网来源仍使用各自已有的查询与目录抓取方式。没有抓取到、没有取得摘要的论文，不能靠 embedding 自动补回来。英文模型不提供可靠的中文跨语言检索保证。

## 本地缓存与运行条件

模型在网页进程内复用；论文向量和查询向量存入搜索 SQLite 库现有的 `paper_embeddings` 表。标题或摘要变化、模型版本或分段配置变化会使对应缓存失效。

配置示例：

```json
{
  "search": {
    "semantic": {
      "cache_folder": ".model-cache/hub",
      "max_updated_papers_per_run": 500
    }
  }
}
```

相对模型缓存路径以服务启动目录为准；从其他目录运行时请改用绝对路径。首次使用需安装项目的 `semantic` 可选依赖，并预先下载固定版本模型：

```powershell
.\.venv\Scripts\python.exe -m pip install ".[semantic]" -c constraints-semantic.txt
.\.venv\Scripts\python.exe -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('BAAI/bge-small-en-v1.5', revision='5c38ec7c405ec4b44b94cc5a9bb96e735b38267a', device='cpu', trust_remote_code=False, cache_folder='.model-cache/hub')"
```

交互搜索强制只加载本地模型，不自动下载、不调用付费 embedding API。模型或依赖不可用时回退关键词，并在页面明示。每次默认最多新计算 500 篇，优先有摘要的记录；既有向量不占新计算预算。超额候选会显示待计算数量，不能把部分覆盖理解为全库语义搜索，后续搜索继续补算。

## API 和评测

`POST /searches` 新增 `ranking: hybrid | semantic | lexical`，省略时网页 API 默认 hybrid。请求保存所选模式；响应的 `ranking`、`ranking_version` 表示最终实际方式，`ranking_details` 保存模型签名、编码/缓存/待计算数量、摘要覆盖和回退原因。检索状态增加 `ranking`。每篇结果保留词项分数，并按实际计算补充 `semantic_score` / `hybrid_score`。

导出文件保留这些分数和排序信息，不修改旧快照及人工/AI 标注来源。反馈不会自动训练模型；本轮没有更换 Daily 的排序配置。

2026-11-04 在隔离数据库副本中验证：原库 260 篇，经过正式发表和有效摘要筛选后 58 篇全部完成向量匹配。混合模式首次约 7.42 秒，进程内缓存复用后约 0.063 秒。均不含联网时间，不代表所有机器或更大规模下的耗时。

使用原冻结池，不新增或修改标签，对唯一一个人工标注完整的开发查询（20 篇）比较：

| 方法 | 前 5 篇有帮助（1 或 2） | 前 5 篇直接相关（2） | nDCG@5 |
|---|---:|---:|---:|
| 关键词 | 3/5 | 1/5 | 0.503 |
| 语义＋关键词 | 4/5 | 2/5 | 0.656 |
| 纯语义 | 3/5 | 1/5 | 0.312 |

这是旧冻结池内的排序分析，保留其原有题名、摘要和文献类型，并未应用今天的发表筛选重新构造样本。它不是当前全库搜索效果或独立测试成绩；其余查询没有完整人工标签，不计算相关性指标，也不以 AI 判断替代。后续应冻结不同排序结果的合并池，增加不同研究问题的人工判断，再决定是否调整模型或融合规则。
