# 来源抓取可靠性：实施与验证

日期：2026-11-04。对应 [设计方案](source-fetch-reliability-plan.md)。

## 已落地的流程

继续使用原有适配器、独立 worker 和父进程事务提交。官方目录首先写入 `source_tasks`，保存论文链接、目录标题、目录哈希和规则版本，再访问详情页。只有取得真实标题和作者后才创建候选及主会成员证据；目录条目本身不作为已核验论文。

目录状态中的 `entries` 保存逐篇详情/摘要状态、尝试次数、最近尝试、失败代码和下次尝试时间。原有 `done` 仍兼容。详情中断后保留剩余任务，重复抓取不会创建新的论文身份。目录结构错误作为目录任务延期，其他目录可以继续。目录中的 `exhausted` 表示详情发现进度，不等于摘要覆盖完整。

单篇 404、身份字段缺失、解析错误与网络错误先记录在任务上；连续两次网络失败停止来源。429、401、403、挑战页面立即停止访问，不被单篇隔离吞掉。请求次数和本轮截止时间耗尽属于 `partial`，不触发网站故障冷却。单篇网络失败延期一小时，404/解析缺失通常七天，访问限制一天，429 尊重 Retry-After；来源级网络冷却仍沿用已有策略。界面分别显示本轮失败、延期补查与来源冷却。

Windows 下终止 worker 时结束其进程树，覆盖虚拟环境启动器背后的真实 Python 进程。数据库提交错误继续向上传播，不当作单篇网页错误处理。

## 摘要补全与真实性

- 手动搜索启用原有精确补全机制，最多分配八个补全任务；各来源最多预留请求额度四分之一的任务数，且最多八个。重试仍计入每来源与整轮既有预算，没有额外请求通道。
- 优先处理当前查询词项匹配较多、没有有效摘要的已有候选。官方 URL、OpenAlex DOI 和 Crossref DOI 查找共用预算；Crossref 只有显式启用后才参与。
- 官方页面补全验证标题与作者；聚合接口验证 DOI。失败任务保留原因及重试时间，不能以标题相同代替身份确认。官方页面定位增加已支持的 CVF 和 AAAI 详情路径，主会资格仍由原核验规则决定。
- 统一使用明确摘要容器，覆盖实际 OJS/AAAI `section.abstract` 结构，排除摘要标题及引用/下载导航文本。取消将通用 `description` 自动当作摘要的回退。
- 保存摘要状态、来源、获取时间、提取方式和解析版本。已有有效摘要不被空内容或冲突文本覆盖；冲突响应保留在来源记录中，候选记录显示冲突诊断。
- 解析版本升级可重新处理已缓存的详情响应，不改写冻结历史快照。

未启用 JSON-LD 或新增摘要元数据分支：本轮已有真实页面样本未确认可用的对应字段。离线检查保证页面内多个 JSON-LD 对象及站点 description 不会被误取为摘要。后续只有取得平台真实样本并完成身份/冲突检查后才增加提取方式。

## 缓存与数据兼容

新增一张职责单一的 `source_http_cache` 表，迁移版本为 5；发现与重试状态仍复用 `source_tasks`。缓存由 worker 原子写出、父进程提交；目录/详情事务和缓存提交分别保留，不要求失败页面生成候选。

| 项目 | 当前行为 |
|---|---|
| 官方目录 | 六小时内复用解析后的条目；到期可通过响应缓存重新验证 |
| 官方详情 | 响应缓存七天；已成功详情不在每次搜索重复访问 |
| API 查询/精确查询 | 默认响应缓存五分钟，未到期不请求网络 |
| 条件请求 | 支持 ETag / Last-Modified；304 仅在有缓存正文时复用 |
| 无正文的 304 | 重新请求，仍计入预算，不能计为空结果成功 |
| 容量 | 每个数据库最多 64 条、64 MiB；写入时清理超过十四天的旧条目 |
| 缓存键 | 对 URL、请求参数、必要请求头上下文取哈希，不保存凭据原文 |
| 故障与取消 | 已写出的完整页和缓存可提交；中断时保留已发请求计数 |

目前各适配器访问主机互不重叠，沿用已有主机间隔，没有增加并发。未来若多个适配器共享主机，需在新增适配器时统一主机访问节奏，不能直接复制来源预算。

搜索与 Daily 数据库保持隔离。迁移在本地搜索库副本上验证，论文身份、投递相关表、收藏、人工/AI 标注和搜索快照的逻辑内容不变。现有 Daily 预览隔离测试通过，本轮没有真实邮件投递或私有历史重置。

## 验证结果

全量离线检查 173 项通过，覆盖单篇失败隔离、限流、恢复、错误身份、摘要保护、缓存命中、304、容量约束、目录规则与真实 Windows 子进程终止。

固定响应对照使用相同目录、首篇 404 和后一篇正常详情，允许三次请求：旧官方抓取逻辑用两次请求后退出，保存零篇；新逻辑用三次请求保存一篇，并保留目录断点。该结果只证明这一故障恢复场景，不代表总体推荐效果。

两轮小预算联网验证使用独立数据库，不使用用户标注或 Daily 状态。包含访问说明检查，总计 **17 次 HTTP 请求**：PMLR 4、ACL 7、NeurIPS 2、OpenAlex 4，均未超过每来源 10 次和总计 40 次上限。

| 观察项 | 首轮 | 续抓轮 |
|---|---:|---:|
| 采集请求数（不含访问说明） | 8 | 3 |
| 新增候选 | 6 | 2 |
| 累计候选池有效摘要 | 5/6 | 7/8 |
| OpenAlex 采集请求 | 1 | 0（缓存命中） |
| 完成耗时 | 约 6.9 秒 | 约 1.7 秒 |

两轮处理的论文不完全相同，不能把覆盖比例或耗时差直接当作同池算法提升。NeurIPS 的 robots.txt 与目录访问均遇到网络超时；ACL 续抓时一篇连接失败，另一篇仍成功。联网中发现延期目录被显示为“空结果”的问题后，已补充延期诊断并用离线检查验证，没有为此重复联网测试。

PMLR、ACL 的 robots.txt 返回 404，代表未取得 robots 规则，不等于所有访问方式均获许可。OpenAlex 官方开发入口跳转至官方帮助站并成功返回；本轮没有访问受限全文或绕过挑战页。OpenAlex 采集响应报告成本 0.001 美元；未调用 LLM。

## 使用与回退

仍使用既有搜索网页和 `search` / `run` CLI，无需新后台服务。首次查询保存目录后，后续查询可继续处理候选或补全摘要；“仅显示有摘要”只是展示过滤，覆盖统计应以过滤前候选池为准。

部署前备份 SQLite（包含 WAL 的一致性快照），停止旧服务后安装，随后在正常联网环境启动。旧搜索记录不会随新解析器变化；重新搜索才能看到新结果和诊断。

回退代码时可保留新增缓存表，旧代码忽略它。不要直接覆盖已经产生新标注或新投递的数据库；如确需恢复副本，先核对新增状态。无需重置 GitHub 私有状态历史。

本轮没有实现 PDF 抽取、默认浏览器渲染、常驻爬虫、模型重训或自动新增 GitHub 定时工作流。也不保证站点网络可达性；NeurIPS 当前仍需保留可解释的失败和恢复路径。
